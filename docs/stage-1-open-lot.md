# 1단계 — 공터 자유 주행 (PoC 목표 지점)

> **검증 질문: "운전하는 느낌"이 나는가?**

## 목표

아무도 없는 넓은 공터에서 자유롭게 주행한다. 시나리오도, 목표도, 실패도 없다.

**이 단계가 프로젝트 전체의 절반 이상이다.** 2~4단계는 여기서 만든 조작감 위에 상황을 얹는 작업이므로, 여기서 느낌이 안 나오면 그 위에 무엇을 쌓아도 소용없다.

PoC는 여기까지다. 이 지점에서 계속 진행할지 판단한다.

## 산출물

1. 깊이 단서가 갖춰진 공터 씬
2. 핸들 각도 모델이 반영된 조향 (키보드 + 마우스)
3. 액셀·브레이크·기어(D/N/R)
4. 운전석 시점의 3D 핸들
5. **런타임 튜닝 패널**
6. **텔레메트리 표시**

## 가장 먼저 만들 것: 튜닝 인프라

기능처럼 보이지 않지만 **이것이 1단계의 핵심 산출물**이다. 조작 수치는 20개 남짓이고 서로 얽혀 있어 한 번에 맞출 수 없다. 수치를 바꿀 때마다 코드를 고치고 리로드하면 여기서 프로젝트가 멈춘다.

### 튜닝 패널 (lil-gui)

`config/vehicle-params.ts`의 모든 값을 슬라이더로 노출한다. 최소한:

- 서스펜션 (강성, 압축 감쇠, 이완 감쇠, 최대 스트로크)
- 타이어 (전방 마찰, 횡방향 강성)
- 엔진력, 브레이크력, 앞뒤 브레이크 배분
- 핸들 회전 속도, 조향비, 복원 속도
- 크립 강도

프리셋 저장/불러오기(localStorage + JSON 내보내기)를 붙이면 "어제 그 느낌"으로 되돌아갈 수 있다. 튜닝을 여러 날에 걸쳐 하게 되므로 실질적으로 필요하다.

### 텔레메트리

**"왜 이상한지"를 눈으로 봐야 고칠 수 있다.** 화면 구석에 표시:

| 항목 | 왜 필요한가 |
|---|---|
| 속도 (km/h) | 기본 |
| 핸들 각도 / 앞바퀴 각도 | 조향 모델이 의도대로 도는지 |
| 기어 (D/N/R) | 후진 상태머신 확인 |
| 바퀴별 접지 여부 | 튀어오름·전복 원인 파악 (`wheelIsInContact`) |
| 바퀴별 서스펜션 압축량 | 서스펜션이 바닥을 치는지 (`wheelSuspensionLength`) |
| 바퀴별 횡방향 임펄스 | 미끄러짐 판단 (`wheelSideImpulse`) |
| 엔진력 / 브레이크력 | 입력이 실제로 전달되는지 |

## 씬 구성 — 깊이 단서

평평하고 텍스처 없는 면은 깊이감을 죽인다. 예쁠 필요는 없지만 **거리는 반드시 읽혀야 한다.**

| 요소 | 사양 | 역할 |
|---|---|---|
| **바닥 격자** | 1m 간격 보조선, 5m 간격 강조선 | 거리·속도 판단의 1차 단서. 가장 중요 |
| **방향광 + 그림자** | 그림자맵, 차량과 물체 모두 캐스팅 | 물체가 지면 어디에 붙어 있는지 알려줌 |
| **원거리 fog** | 80~150m 페이드 | 소실점 강조, 원경 정리 |
| **참조물** | 라바콘, 기둥, 벽 몇 개를 흩어 배치 | 크기를 아는 물체가 있어야 거리 추정이 됨 |
| **모서리 강조** | 기둥·벽에 줄무늬 | 3단계 여유 폭 가늠의 예행 연습 |

공터 크기는 200m × 200m 정도. 가장자리에 낮은 벽을 둘러 경계를 명확히 한다.

**차량 크기를 실제와 맞춘다.** 라바콘(0.7m), 주차 구획(2.5m × 5m) 같은 실제 치수의 물체를 배치해야 사용자가 차폭 감각을 학습할 수 있다. 여기서 스케일이 틀리면 4단계 전체가 무의미해진다.

## 차량 파라미터 초기값

**전부 출발점일 뿐이며 튜닝 대상이다.** Rapier의 차량 컨트롤러는 Bullet의 `btRaycastVehicle` 계열이므로, 그쪽 튜닝 자료를 참고할 수 있다.

| 파라미터 | 초기값 | 조정 방향 |
|---|---|---|
| 차체 질량 | 1200 kg | |
| 무게중심 | 기하 중심 아래 0.2~0.3m | 높으면 전복, 너무 낮으면 롤이 사라져 부자연스러움 |
| 바퀴 반지름 | 0.33 m | |
| 서스펜션 rest length | 0.3 m | |
| 서스펜션 강성 | 24 | 낮으면 물렁하게 출렁, 높으면 딱딱하고 튐 |
| 압축 감쇠 | 0.82 | |
| 이완 감쇠 | 0.88 | 낮으면 과속방지턱 후 계속 출렁임 |
| 최대 서스펜션 스트로크 | 0.3 m | |
| 타이어 마찰 (frictionSlip) | 10.5 | 낮추면 잘 미끄러짐 |
| 횡방향 강성 | 0.5~1.0 | 저속 떨림의 주범. 3단계에서 재조정 |
| 최대 엔진력 (구동륜 각각) | 2000 N | 1200kg, 0→100km/h 약 10초 기준 |
| 최대 브레이크력 (총합) | 9600 N | 감속 8m/s² 기준 |
| 앞뒤 브레이크 배분 | 65 : 35 | 실차와 동일. 노즈다이브가 살아남 |
| 엔진 브레이크 | 최대 브레이크력의 5% | 액셀을 뗐을 때 상시 |
| 크립 엔진력 | 최대의 3~5% | 오토 차량이 스르륵 굴러가는 힘 |

### 엔진력 커브

`힘 = 최대힘 × throttle` 로 두면 최고속도가 무한히 올라간다. **속도가 오를수록 힘이 줄어드는 커브**를 넣으면 최고속도가 자연스럽게 생긴다.

```
엔진력 = 최대힘 × throttle × (1 - 현재속도 / 최고속도)
```

거친 근사지만 1단계에는 충분하다. 정교한 토크 커브·변속기는 이 게임의 목적에 필요 없다.

### 크립 (creep)

오토 차량은 브레이크만 떼도 스르륵 굴러간다. 지금은 사소해 보이지만 **4단계 주차에서는 조작의 절반이 크립이다.** 실제로 좁은 주차장에서는 액셀을 거의 안 밟고 크립과 브레이크만으로 움직인다.

1단계에서 넣어두고 튜닝해야 4단계에서 다시 만들지 않는다.

## 입력

자세한 조향 모델은 [steering-model.md](./steering-model.md) 참조. 1단계에서 구현할 범위:

### 키보드 (기본)

| 키 | 동작 |
|---|---|
| W / ↑ | 액셀 (0→1로 램프. 즉시 100%가 되지 않게) |
| S / ↓ | 브레이크. 정차 상태에서 계속 누르면 R로 전환 |
| A, D / ←, → | 핸들 회전 (누르는 동안 각도 누적) |
| Space | 핸들 급속 복귀 (실제 손을 놓았을 때) |
| R | 리스폰 |
| C | 시점 전환 (운전석 / 3인칭) |

### 마우스 (Pointer Lock)

화면 클릭으로 포인터 락 진입, 좌우 이동량을 핸들 각도로 누적. 감도는 "몇 cm 이동에 한 바퀴"로 노출한다.

**키보드와 마우스의 정밀도 차이를 직접 비교하는 것이 1단계의 부수적 목표**다. 3~4단계에서 어느 쪽을 주력으로 삼을지 여기서 판단한다.

### 기어 상태머신

브레이크와 후진이 같은 키이므로 명시적인 상태 관리가 필요하다.

```
D 상태 + 브레이크 + 속도 ≈ 0 이 일정 시간(0.3s) 유지  →  R 전환
R 상태 + 액셀 + 속도 ≈ 0 이 일정 시간 유지            →  D 전환
```

`currentVehicleSpeed()`로 판단하고, **현재 기어를 화면에 반드시 표시**한다. 표시 없이는 사용자가 혼란스럽다.

## 3D 핸들

운전석 시점이므로 화면 하단에 핸들이 보인다. 이것을 `steeringWheelAngle` 그대로 회전시킨다.

- 12시 방향에 마커 하나 (회전량 직관적 인지)
- 락 도달 시 정지 + 소리
- 조향각 수치 표시는 켜고 끌 수 있게

포스 피드백을 대체하는 유일한 수단이므로 대충 만들지 않는다.

## 튜닝 순서

한 번에 다 맞출 수 없다. 이 순서로 하나씩 고정해 나간다.

1. **정적 자세** — 차를 세워두고 서스펜션이 적절히 눌리는가. 바닥을 뚫거나 공중에 뜨지 않는가
2. **직진 가속·제동** — 조향을 건드리지 않고 가속감, 제동 거리, 노즈다이브만 본다
3. **저속 조향** — 20km/h 이하에서 핸들을 끝까지 감았을 때 회전 반경이 실제(약 5~6m)와 비슷한가. **떨림이 없는가**
4. **중속 조향** — 40~60km/h에서 차선 변경 정도의 조향. 롤이 자연스러운가, 뒤가 흐르지 않는가
5. **핸들 회전 속도** — 실제 손 속도와 비교. 너무 빠르면 게임 같고, 느리면 답답하다
6. **자동 복원** — 코너를 빠져나올 때 핸들을 놓았을 때의 거동
7. **크립** — 브레이크를 뗐을 때 굴러가는 속도 (실차는 약 7~10km/h에서 안정)

각 단계에서 **한 번에 하나의 수치만 바꾼다.** 여러 개를 동시에 만지면 무엇이 효과가 있었는지 알 수 없다.

## 완료 판정

기술적 완료가 아니라 **감각적 완료**를 본다.

- [ ] 차가 저절로 뒤집히거나 진동하지 않는다
- [ ] 저속 풀조향에서 떨림이 없다
- [ ] 회전 반경이 실제 승용차와 비슷하다 (최소 회전 반경 5~6m)
- [ ] 격자 바닥을 보고 속도를 가늠할 수 있다
- [ ] 라바콘 옆을 지날 때 차폭이 감각적으로 읽힌다
- [ ] 브레이크를 밟았을 때 앞으로 쏠린다
- [ ] 액셀을 떼면 차가 자연스럽게 감속한다
- [ ] 브레이크를 떼면 크립으로 스르륵 굴러간다
- [ ] 화면의 핸들을 보지 않고도 대략 얼마나 감았는지 안다
- [ ] **"운전하는 느낌이 난다"** — 최종 판단

마지막 항목은 주관적이지만, 이 게임에서는 이것이 유일하게 중요한 기준이다.

## 리스크

| 리스크 | 징후 | 대응 |
|---|---|---|
| 저속 풀조향 떨림 | 주차 속도에서 차가 부르르 떨림 | 횡방향 강성 조정, 물리 스텝 세분화 검토. 3단계에서 저속 전용 파라미터 세트로 분리 |
| 전복 | 조금만 꺾어도 뒤집힘 | 무게중심 낮추기, 롤 영향도 조정 |
| 서스펜션 바닥 침 | 요철에서 덜컹 | 스트로크·강성 증가 |
| 튜닝이 끝나지 않음 | 며칠째 슬라이더만 만짐 | 완료 판정 체크리스트로 끊는다. 완벽함이 아니라 "느낌이 나는가"가 기준 |

# 구현 노트 (완료 후 기록)

## 1. 오른쪽은 -X 다 — 0단계 문서의 좌표 규칙이 틀렸다

0단계에서 "전방 +Z, 오른쪽 +X" 로 적어뒀는데 **틀렸다.** 오른손 좌표계에서
`right = forward × up` 이므로, forward=+Z / up=+Y 이면 right = **-X** 가 된다.

이 실수가 만든 결과가 조용해서 위험했다.

- 운전석을 `x = -0.38` 에 뒀는데, 그게 **오른쪽**이었다 → 우핸들 차가 되어 있었다
- `D` 키(우조향)를 누르면 차가 **왼쪽으로 돌았다**
- 0단계 검증 도구는 "핸들 +면 +X 로 간다"를 통과시켰다. 검사식 자체가 틀렸으니
  테스트가 초록불이어도 의미가 없었다

**발견 경위** — 3인칭 스크린샷에서 `x = -24` 에 그린 주차 구획이 화면 오른쪽에
보였다. 물리 수치가 아니라 그림을 보고 알았다.

**대응** — 축 방향(`axleCs`)을 뒤집는 방법은 쓸 수 없다. 뒤집으면 전후진까지
반대가 된다 (전진 명령에 차가 z=-7.28 로 갔다). 대신 조향각을 물리에 넘기는
지점에서 부호를 뒤집었다.

```ts
// 핸들 + = 우회전 = -X 방향
controller.setWheelSteering(i, -roadWheelAngle)
```

검증 항목에 `운전석이 왼쪽(+X)에 있다` 를 추가했다. 좌핸들은 이 프로젝트의
전제(한국)라서 회귀하면 안 되는 값이다.

## 2. `currentVehicleSpeed()` 는 전방 속도가 아니다

Rapier 의 `currentVehicleSpeed()` 는 속도 **벡터의 크기**다. 낙하·경사 성분이
그대로 포함된다. 평지에서는 차이가 없어 0단계에서는 드러나지 않았다.

발견 경위 — 타행(액셀 뗌) 테스트에서 차가 60 → 71 km/h 로 **가속**했다.
실제로는 200m 공터 밖으로 나가 자유낙하 중이었고, 낙하 속도가 주행 속도로
읽힌 것이다.

**대응** — `forwardSpeed()` 를 만들어 차체 전방(+Z)에 투영한 속도를 쓴다.
3단계 램프에서는 이 차이가 크립·기어 판정을 직접 망가뜨린다.

부수적으로, 공터 경계벽을 물리 객체로 세워 차가 지면 밖으로 나가지 못하게 했다.

## 3. 크립은 일정한 힘으로는 안 된다

일정한 힘(90N)으로 밀면 주행 저항과 균형을 이루는 지점에서 멈춘다.
목표 8km/h 에 대해 4.2km/h 에서 안정돼 버렸다.

**대응** — 목표 속도에 가까울수록 약해지는 비례 제어로 바꾸고 힘을 키웠다.

```ts
const deficit = 1 - speedInGearDirection / creepSpeed
engineForce += forward * creepForce * deficit
```

현재 7.1 km/h 에서 안정된다. 실차(7~10km/h)와 비슷하다.

## 4. 운전석 배치는 수치보다 스크린샷으로 잡힌다

핸들 위치, 대시보드 높이, 보닛 위치는 계산으로 한 번에 안 맞았다.

- 핸들이 눈에서 0.44m → 화면 절반을 가림. 0.62m 로 밀어냄
- 12시 마커를 림 한가운데 두면 **림이 마커를 가로질러 두 조각으로 보인다.**
